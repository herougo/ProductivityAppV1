# Task Plan: Define All Models

## Overview

This task implements all database models for the productivity tracking application in the `productivity_core` Django app. The models follow the schema defined in the plan overview and include proper relationships, field types, and constraints.

## Files to Modify

### 1. `productivity_app/productivity_core/models.py`

**Action:** Replace the default file content with complete model definitions

**Implementation Details:**

Create the following 7 models with their respective fields and relationships:

#### Model 1: Epic
- **Purpose:** Groups related tasks together
- **Fields:**
  - `user` - ForeignKey to User (CASCADE)
  - `name` - CharField(max_length=100)
  - `display_name` - CharField(max_length=200)
  - `colour` - CharField(max_length=7) for hex color codes
  - `date_created` - DateTimeField(auto_now_add=True)
- **Relationships:** user → User (CASCADE)

#### Model 2: WorkflowState
- **Purpose:** Represents task statuses (e.g., Backlog, In Progress, Done)
- **Fields:**
  - `user` - ForeignKey to User (CASCADE)
  - `order` - IntegerField (for ordering states)
  - `name` - CharField(max_length=100)
  - `display_name` - CharField(max_length=200)
  - `is_on_board` - BooleanField (whether shown on Kanban board)
  - `is_final` - BooleanField (whether this is a completion state)
  - `date_created` - DateTimeField(auto_now_add=True)
- **Constraints:**
  - UniqueConstraint on (user, order)
- **Relationships:** user → User (CASCADE)

#### Model 3: Sprint
- **Purpose:** Represents week-long sprints
- **Fields:**
  - `user` - ForeignKey to User (CASCADE)
  - `start_date` - DateField
  - `end_date` - DateField
- **Relationships:** user → User (CASCADE)
- **Notes:** Will need custom validation to ensure start_date < end_date

#### Model 4: Task
- **Purpose:** Core entity representing a unit of work
- **Fields:**
  - `user` - ForeignKey to User (CASCADE)
  - `name` - CharField(max_length=100)
  - `display_name` - CharField(max_length=200)
  - `description` - TextField (blank=True)
  - `current_status` - ForeignKey to WorkflowState (SET_NULL, null=True)
  - `epic` - ForeignKey to Epic (SET_NULL, null=True, blank=True)
  - `current_sprint` - ForeignKey to Sprint (SET_NULL, null=True, blank=True)
  - `date_created` - DateTimeField(auto_now_add=True)
  - `date_updated` - DateTimeField(auto_now=True)
- **Relationships:**
  - user → User (CASCADE)
  - current_status → WorkflowState (SET_NULL)
  - epic → Epic (SET_NULL)
  - current_sprint → Sprint (SET_NULL)

#### Model 5: TaskWorkflowStates
- **Purpose:** Audit log of task status changes
- **Fields:**
  - `user` - ForeignKey to User (CASCADE)
  - `task` - ForeignKey to Task (CASCADE)
  - `status` - ForeignKey to WorkflowState (CASCADE)
  - `date_updated` - DateTimeField(auto_now_add=True)
- **Relationships:**
  - user → User (CASCADE)
  - task → Task (CASCADE)
  - status → WorkflowState (CASCADE)

#### Model 6: TaskCompletionLog
- **Purpose:** Records task completion metrics
- **Fields:**
  - `task` - OneToOneField to Task (CASCADE, primary_key=True)
  - `minutes_logged` - IntegerField
  - `date_updated` - DateTimeField(auto_now=True)
- **Relationships:** task → Task (CASCADE, primary key)
- **Notes:** Uses OneToOneField as primary key

#### Model 7: PastSprintMetadata
- **Purpose:** Stores aggregated metrics for completed sprints
- **Fields:**
  - `sprint` - OneToOneField to Sprint (CASCADE, primary_key=True)
  - `number_of_tasks_completed` - IntegerField
  - `minutes_of_work_completed` - IntegerField
  - `date_completed` - DateTimeField
- **Relationships:** sprint → Sprint (CASCADE, primary key)
- **Notes:** Uses OneToOneField as primary key

## Implementation Guidelines

### Imports Required
```python
from django.db import models
from django.contrib.auth.models import User
```

### Field Type Mapping
- IDs: Auto-generated by Django (implicit AutoField primary keys)
- user_id references: `ForeignKey(User, on_delete=models.CASCADE)`
- Strings (name, display_name): `CharField` with appropriate max_length
- Long text (description): `TextField`
- Dates/Times:
  - `DateTimeField(auto_now_add=True)` for date_created
  - `DateTimeField(auto_now=True)` for date_updated
  - `DateField` for start_date/end_date
- Numbers: `IntegerField`
- Booleans: `BooleanField`
- Colors: `CharField(max_length=7)` for hex codes like #FF5733

### Foreign Key Configuration
- Use `related_name` for reverse lookups (e.g., `related_name='epics'`)
- SET_NULL behavior: `on_delete=models.SET_NULL, null=True, blank=True`
- CASCADE behavior: `on_delete=models.CASCADE`

### Model Organization
Order models to avoid forward references:
1. Epic (depends only on User)
2. WorkflowState (depends only on User)
3. Sprint (depends only on User)
4. Task (depends on User, WorkflowState, Epic, Sprint)
5. TaskWorkflowStates (depends on User, Task, WorkflowState)
6. TaskCompletionLog (depends on Task)
7. PastSprintMetadata (depends on Sprint)

### Additional Considerations
- Add docstrings to each model class explaining its purpose
- Keep models clean and focused on data structure
- __str__ methods, Meta classes, and helper methods will be added in task 06
- Validation logic (e.g., start_date < end_date) will be added in task 06
